# Vision

`herdr-one-piece` exists so that one captain can use firstmate's crew with confidence while keeping independent work close at hand.
It serves the individual captain through an optional One Piece interface in Herdr.
It owns exactly one thing: the presentation and navigation of the captain's existing fleet and personal terminals.

## Firstmate supplies the governing vision

This vision extends [firstmate's vision](https://github.com/kunchenguid/firstmate/blob/main/VISION.md).
Its baseline is the [revision reviewed for this draft](https://github.com/kunchenguid/firstmate/blob/90cd351ac8b828d7074fe4a432acda246355bec7/VISION.md).
Firstmate's commitments to one captain, explicit authority, durable obligations, supervised delegation, and vendor independence govern this extension.
This document adds presentation commitments and does not replace those rules with a second command policy.
Changes to the upstream vision require an explicit compatibility review rather than silently changing this extension's meaning.
The extension remains optional, and removing it leaves firstmate's contracts and records intact.

## A calm fleet keeps firstmate within reach

The primary path leads to firstmate, which carries the captain's direction and gathers worker reports.
The interface makes outcomes, decisions, and failures legible without requiring the captain to patrol every worker.
Machine aliases may use islands such as Water 7 and Wano, with real machine identities visible beside them.
All machines remain visible in the sidebar, and each coordinator appears under its actual machine.
A ship only expands or collapses its characters.
Luffy stays first beneath Sunny and opens the coordinator session.
Worker selection opens the worker's own workspace for inspection without making worker supervision the captain's routine burden.
Direct access does not itself grant permission to bypass firstmate's reporting or authority rules.
Any proposed exception for directly commanding secondmates or workers requires an explicit decision rather than an inference from a clickable character.

## Independent work stays independent

A coordinator workspace starts with one coordinator session and can hold personal terminals created by the captain.
Personal terminal commands do not become messages or delegated tasks for firstmate or its workers.
Workers retain their own workspaces, separate from personal terminals.
A grid keeps independent work beside the coordinator without transferring ownership between them.
Changing selection or enlarging a pane preserves running sessions.
Close identifies the terminal and explains that its process ends.
Closing a view or session does not claim that firstmate's durable obligations have been completed or discarded.

## Presentation reflects authority and durable truth

Herdr executes terminals and manages workspaces, while firstmate owns delegation, supervision, and the records of work.
The mod neither grants autonomy nor interprets a status indicator as authorization.
It does not invent replies, permissions, completed work, or restored agent conversations.
Reopening the interface reconciles its display with actual sessions and durable records instead of treating browser memory as truth.
Themed navigation preserves machine identity, workspace ownership, and existing running sessions.
Native integration must verify these guarantees before the implementation promises them.
Exact display mechanics use deterministic code rather than spending agent context on animation or navigation.
The Herdr-specific interface does not introduce Herdr dependencies into firstmate's shared command contracts.

## Artwork conveys state without creating work

Custom One Piece pixel artwork provides one consistent visual language.
Idle workers sleep, working workers walk, and workers needing attention sit.
A sitting worker indicates a condition to understand, not an instruction to bypass firstmate and intervene directly.
Each character retains the actual worker name or task beside it.
Character assignments remain stable for surviving workers as other workers enter or leave.
Sunny and Luffy establish the initial crew, with Chopper, Franky, and numbered generic Pirates supporting workers.
Additional workers never depend on completing a named character catalog.
More ships and crews are welcome when they preserve the same ownership and navigation rules.
Animation supports recognition without concealing failures, decisions, or risks.

## Scope

This project is an optional Herdr presentation extension, not a scheduler, a replacement terminal system, or a second firstmate implementation.
It adds no command hierarchy, merge authority, or automatic delegation policy.
Personal preferences, credentials, and fleet records remain private to the captain's home.
The imported prototype records visual intent, while accepted decisions and this inherited policy take precedence over simulated behavior.
This extension remains a draft pending author review, including the boundary between inspection and direct commands.

A change aligns when it reduces the captain's attention burden while preserving firstmate's authority, durable truth, and independent terminal work.
A change should be resisted when visual convenience creates competing command paths, hides uncertainty, assumes consent, or makes firstmate depend on this interface.

# Repository guidance

Read VISION.md first.
It extends firstmate's governing vision and is the authoritative local acceptance policy.

## What exists

The prototype and artwork live under prototype/.
The current preview is generated from prototype/flow/app.js and prototype/flow/screen.html.
Rebuild it with `python3 prototype/flow/build.py` rather than editing prototype/index.html.
The docs directory contains the prototype inventory, artwork coverage, and historical specification.
The experimental native mod lives in mods/one-piece, with its layout in layouts/one-piece.json.
Read docs/NATIVE-INTEGRATION.md for verified behavior and outstanding checks.

## Resolve design conflicts

VISION.md takes precedence over docs/PROTOTYPE-SPEC.md and the browser simulation.
The snapshot's proposed direct worker input conflicts with inspection-only supervised worker and secondmate views.
The snapshot's cached offline fleet conflicts with the approved distinct offline presentation.
Native terminal embedding alone does not prove inspection-only access.
Preserve independent personal terminals and the accepted Unsupervised mode without adding another command path into the supervised fleet.

## Native development

Read the installed ~/.config/herdr-app/AGENTS.md and relevant .d.ts declarations before relying on Herdr behavior.
Those files are generated by Herdr and must not be edited.
Mods use native JavaScript UI elements, not browser HTML or CSS.
Keep this project's mod and layout separate from shipped Herdr files and existing user layouts.
Never use actual worker sessions for destructive integration tests.
Do not infer coordinator roles from names, artwork, or directories.
Treat role registration details in the prototype specification as proposals until verified against firstmate's actual integration.

## Verification

Run `git diff --check` for every change.
For prototype behavior changes, rebuild, open prototype/index.html with chrome-devtools-axi, and run `python3 prototype/flow/check-browser.py`.
For a native mod, run `herdr-app check <mod-folder>` and inspect its behavior in the running application.
The native check only exercises initial rendering and cannot establish session preservation, remote recovery, or inspection-only access.
Record those limits explicitly when reporting results.
Review boards and verdict transcripts stay outside this repository.

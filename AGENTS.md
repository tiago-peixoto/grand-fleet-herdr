# Repository guidance

Read VISION.md first.
It extends firstmate's governing vision and is the authoritative local acceptance policy.

## What exists

The prototype and artwork live under prototype/.
The native-flow reference is ~/Workspace/.lavish/grand-fleet-native-prototype/index.html and its Lavish session 0782435952d24d57.
The browser simulation is generated from prototype/flow/app.js and prototype/flow/screen.html.
Rebuild it with `python3 prototype/flow/build.py` rather than editing prototype/index.html.
The docs directory contains the prototype inventory, artwork coverage, and historical specification.
The experimental native mod lives in mods/one-piece.
The installer generates its base module and layout from the destination Herdr installation.
Read docs/THIN-MOD.md for the current simplification and candidate verification.
Read docs/NATIVE-INTEGRATION.md for verified behavior and outstanding checks.

## Resolve design conflicts

VISION.md takes precedence over docs/PROTOTYPE-SPEC.md and the browser simulation.
Worker and secondmate terminals accept direct typing.
Preserve native workspace and terminal behavior beneath the fleet sidebar.
The sidebar uses native Spaces and Agents regions, each with one scrolling list.
Ships identify every space containing a live agent, and clicking a ship selects that space.
A space without a captain is a generic fleet whose agents are all crewmates.
Every agent is a crewmember, and captain artwork appears only for detected or manually marked Firstmate instances.
Retain native grouping, sorting, pinning, workspace menus, and terminal navigation.
Do not reintroduce custom workspace ownership, worker associations, or task polling.
The one exception changes artwork only: a Space of one detected captain's workers flies that captain's flag, matched through the `firstmate.home` label.
The mod must work with unmodified firstmate.
Do not infer coordinator identity from terminal names, folders, or process parents.
Do not require firstmate.home.path, firstmate.role, or any Firstmate patch.
Show offline machines distinctly instead of presenting the snapshot's cached offline fleet.
Do not add an inspection-only workspace or custom arrangement workflows.
Preserve independent personal terminals without inventing supervision labels.

## Native development

Read the installed ~/.config/herdr-app/AGENTS.md and relevant .d.ts declarations before relying on Herdr behavior.
Those files are generated by Herdr and must not be edited.
Mods use native JavaScript UI elements, not browser HTML or CSS.
Keep this project's mod and layout separate from shipped Herdr files and existing user layouts.
Never use actual worker sessions for destructive integration tests.
Do not infer coordinator roles from names, artwork, or directories.
Treat role registration details in the prototype specification as proposals until verified against firstmate's actual integration.

## Verification

Run `git diff --check` for every change.
For prototype behavior changes, rebuild, open prototype/index.html with chrome-devtools-axi, and run `python3 prototype/flow/check-browser.py`.
Run `herdr-app check <installed-mod-folder>` after generating the native base module.
Run `node tools/check-parity.mjs <app-home>` against the same Herdr version.
Inspect the interface in the isolated Grand Fleet Lab.
The native check only exercises initial rendering and cannot establish session preservation, remote recovery, or correct terminal adoption.
Record those limits explicitly when reporting results.
Review boards and verdict transcripts stay outside this repository.

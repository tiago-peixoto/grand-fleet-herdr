# Thin Herdr mod implementation plan

**Goal:** Preserve default Herdr usage while showing native parent agents as ships and captains with nested crewmates.

**Architecture:** Generate the adapter base from installed Herdr source and retain the shipped layout structure.
Keep only appearance selection and sprite rendering in the custom runtime.

**Spec:** [Thin mod design](../../THIN-MOD.md).

## Constraints

Never edit shipped Herdr files or change running terminal ownership.
Do not add shortcuts or reinterpret native status.
Use native machine, space, tab, and agent behavior.
Fail installation before mutation when the required upstream surface changes.

## Tasks

- [x] Add compatibility generation and tests for supported source, unsupported source, and precise layout changes.
- [x] Replace custom fleet navigation with the decorated native Agents implementation and test command parity.
- [x] Update installation to generate dependencies and retire owned shortcuts while preserving unrelated settings.
- [x] Update vision and installation documentation to distinguish current guarantees from historical evidence.
- [ ] Verify local and remote disposable sessions in Grand Fleet Lab and compare against the default layout.
- [ ] Review, push the draft pull request, and audit all requirements before completing the goal.

## Review focus

- Unplaced child agents must retain native peek behavior.
- Missing or offline parents must not acquire invented relationships.
- Personal terminals and unrelated agents must retain native actions.
- Upgrades must not overwrite user changes or leave obsolete shortcut bindings.
- New upstream methods and layout controls must survive generation without being silently discarded.
